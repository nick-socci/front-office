# Front Office — rules for agents

Read by every agent on this repo: Claude Code (via `CLAUDE.md`), Codex (natively), and the
subagents they start. The implementer builds against these rules and the reviewer judges
against them, so a rule belongs here, not in one tool's config.

Front Office is a code-first analytics engineering project: real MLB and ESPN fantasy data,
landed as raw JSON, transformed with dbt, stored in DuckDB (BigQuery planned). **The repo is
public and the ESPN league is private.**

## Project shape

- `ingestion/src/front_office/` — Python, fetch-and-save only. It never interprets data.
- `dbt/models/staging/{mlb,espn,idmap}/` — one model per source concept; `intermediate/`
  and `marts/` build on them.
- `dbt/macros/` — all JSON access goes through `fo_json_*`; models never write DuckDB JSON
  syntax directly, because those macros gain BigQuery variants later.
- `dbt/tests/` — singular tests. `dbt/seeds/` — the lookup seeds are generated by
  `scripts/make_espn_seeds.py` and never hand-edited. `espn_reconciliation_residuals.csv`
  is the exception: a register kept by hand, each row naming its league and season and
  carrying its evidence.
- `dbt/models/marts/_exposures.yml` — what reads the marts: the planned dashboard, and one
  exposure per file in `docs/examples/`. `scripts/check_examples.py` (in the gates) fails if
  an example and its exposure disagree, or if the example no longer runs.
- `fixtures/landing/` — committed CI fixtures, generated by `scripts/make_fixtures.py`.
- A capture is a directory `…/fetched_at=<stamp>/` holding `payload.json` and `meta.json`,
  published by one rename (ADR 0014). Read the landing zone only through
  `LandingZone.committed` / `has_landed` / `iter_landed`; never pair or glob files by
  hand. Nothing in it is ever replaced or deleted by code: what is not a capture is moved
  to the quarantine (ADR 0015).
- `data/` — the real season: raw captures (`data/raw/`) and warehouses (`*.duckdb`), local
  only and gitignored. CI only ever sees fixtures.

## Commands

Once per clone: `git config core.hooksPath .githooks` (enables the privacy guard).

```bash
.agentic/gates                                 # everything CI runs, in CI's order
uv run pytest
uv run ruff check && uv run ruff format --check
uv run mypy                                    # strict, on ingestion/src
FO_CI_DUCKDB_PATH=dbt/ci.duckdb uv run sqlfluff lint dbt/models dbt/tests   # from the repo root
cd dbt && DBT_PROFILES_DIR=. uv run dbt build --select <model>          # real season
cd dbt && DBT_PROFILES_DIR=. uv run dbt build --target ci --vars '{anonymize: true}'
```

## Five rules this project learned the hard way

1. **Project `payload` away before any `unnest`.** `unnest` duplicates every other column in
   its SELECT once per output row. Extracting a field alongside `unnest(teams)` copies the
   2.3 MB ESPN roster payload twelve times per period and exhausted 24 GB of memory.
   Compute everything payload-derived in a `header` CTE first, as
   `stg_espn__roster_entries.sql` does. `count(*)` probes hide this, because the optimizer
   prunes the parse.
2. **Never commit league members' data.** No `members`, `owners`, `primaryOwner`,
   `firstName`, `lastName`, `displayName` or `author` keys, and no ESPN account GUIDs, in
   any model, fixture, seed or doc. Fixtures are rebuilt from an allowlist of wanted fields,
   never scrubbed of unwanted ones. The patterns live in `front_office/privacy.py`; the
   fixture test and `.agentic/pre-commit-guard` (the git pre-commit hook) both use them.
3. **Credentials live only in `.env`.** `espn/client.py` is the only module that reads them.
   They never reach a landing file, a sidecar, a log line, or a test.
4. **Components, never rates.** Store at-bats and hits, not AVG. Store `outs_recorded`, not
   innings — "6.1 innings" means 6⅓ and decimal arithmetic on it is silently wrong.
5. **Deduplicate at the entity grain**, never per request, and always with a deterministic
   tie-break. Use `fo_latest_by_entity` / `fo_espn_latest`.

## dbt gotchas

- A seed CSV that gains a **column** needs `dbt seed --full-refresh` locally; dbt otherwise
  reuses the old table schema and DuckDB rejects the mismatch. CI builds from empty, so
  only local builds hit this.
- dbt renders YAML `description:` fields as Jinja: `{{ source(...) }}` in prose is a
  compilation error.
- dbt 1.12: generic test arguments nest under `arguments:`.

## How work is done here

- **Status lives in GitHub issues**, never in markdown. Docs say what was decided and why;
  issues say what is done. Record run evidence as issue comments.
- **Specs** live in `docs/specs/NNNN-slug/` and **ADRs** in `docs/adr/` (see
  `.agentic/config.toml`). `docs/design/` is the pre-spec record and is not edited.
- Tests before models; say what each test is expected to catch. Never weaken a test to
  make it pass — a failing test is usually telling you something true about the data.
- Every model opens with a comment block explaining *why*; CTEs are named for what they
  hold; columns are `snake_case`.
- Correct against fixtures is not correct. Anything that produces numbers is also built
  against the real season, and the numbers are checked against the spec's acceptance
  criteria.
- Commit messages say what changed in the imperative and reference the issue, e.g.
  `Credit started production by slot role, as ESPN does (#10)`. One PR per unit of work;
  a person merges, never an agent.
- Before pushing to an existing PR branch, check `gh pr view <n> --json state`: PRs here
  get merged fast, and a commit pushed to a merged branch is silently orphaned.

## Decisions that are not an agent's to make

Choosing a grain or a column set · deciding what an ESPN field means · whether numbers
reconcile against the real season · anything touching credentials or the NAS backup.
Raise these with the person; don't choose.
